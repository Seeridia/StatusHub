# 团队账号与权限

StatusHub 只使用邮箱密码登录。登录前不填写工作区；一个有效工作区直接进入，多个工作区可选择并随时切换。收藏链接可以指定工作区，但不会改变密码验证。没有有效成员关系时仍可管理个人密码和退出登录。服务账号仅用于 API。

## 首次初始化

在空实例的 API 容器内执行 `statushub-admin setup-link`。打开返回的链接，在 30 分钟内填写邮箱、12–128 字符密码、工作区名称与标识。提交创建首位 Owner 和工作区并自动登录。重复生成链接使旧链接失效，已有用户或工作区后不能再次初始化。链接属于秘密，不要提交到仓库。

此流程不需要邮件服务，也不会把邮箱标记为已验证。管理员可随后在个人账号中请求验证邮件。额外工作区由可信运维创建，Owner 必须是已有用户：

```bash
statushub-admin tenant-create -slug engineering -name Engineering -owner-email owner@example.com
```

## 角色

| 角色 | 工作区权限 | 成员和服务账号管理 |
|---|---|---|
| Viewer | 查看状态、事件和投递 | 无 |
| Operator | 日常采集与通知配置 | 无 |
| Admin | 工作区管理 | 仅 Viewer、Operator |
| Owner | 全部工作区权限 | 全部角色 |

不能自行改角色或停用自己。必须保留最后一位有效人员 Owner；机器账号不计入。停用只影响当前工作区，保留其他工作区访问和历史记录。权限在后续请求生效，实时连接每 15 秒重新检查。

## 邮件配置

设置 `STATUSHUB_PUBLIC_URL` 为唯一公开 HTTPS 地址。独立邮件参数为 `STATUSHUB_SMTP_ADDRESS`、`STATUSHUB_SMTP_FROM`、`STATUSHUB_SMTP_USERNAME`、`STATUSHUB_SMTP_PASSWORD`。API 与 worker 使用相同配置加密密钥，邮件任务加密入库、异步发送、重试并清理。

本地使用 Mailpit：SMTP `127.0.0.1:51025`，设置 `STATUSHUB_SMTP_ALLOW_LOCAL_PLAINTEXT=true`；在 `http://127.0.0.1:58025` 查看邮件。生产不使用明文 SMTP。未配置邮件时，邀请入口显示配置缺失。

## 邀请成员

设置 → 成员与邀请，填写邮箱与角色后发送。状态区分等待发送、已提交 SMTP、发送失败和已接受。SMTP 接收不等于进入收件箱。

新用户打开邮件链接、设置密码后一次完成邮箱验证和加入。已有用户先登录匹配邮箱的账号再接受。邀请不会覆盖已有角色、恢复停用成员或重置密码。邀请 7 天有效，可撤销和重新发送；重发使旧链接失效。接受时重新检查邀请人的当前权限。

## 密码与会话

忘记密码统一显示不泄露账号是否存在的提示。重置链接 30 分钟有效且只能使用一次，完成后用新密码登录。个人账号修改密码需原密码，修改和重置均撤销所有浏览器会话。

会话绝对有效期 7 天，闲置 24 小时失效。Cookie 仅包含随机令牌，数据库保存哈希；写操作校验 CSRF。退出当前会话与退出全部会话由服务端撤销。不同标签页可使用同一身份访问不同工作区。

## 服务账号

在设置中创建、停用和轮换。Token 只在创建或轮换结果中展示；更新调用方配置后再使用新 Token，旧 Token 立即失效。列表无法查看已有秘密。短期幂等重试允许取回加密结果，10 分钟后只能确认已完成，不能再次取回秘密。

## 故障定位

错误会区分凭据错误、会话过期、来源配置错误、工作区无权限、邀请失效、限流和邮件不可用，并附请求编号。换域名后更新 Dokploy 保存的 `STATUSHUB_PUBLIC_URL`，重新部署；只修改运行目录会被后续部署覆盖。可信代理仅通过 `STATUSHUB_TRUSTED_PROXIES` CIDR 列表明确授权。

本版本为全新安装基线，不迁移旧账号或业务数据。重装前确认清理范围仅限应用自己的数据库和消息队列，保留其他应用及 Dokploy 数据。
